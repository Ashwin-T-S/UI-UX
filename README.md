## Sprint folders

Every sprint has the same shape.

```
Design-Sprint-1/
  00-READ-FIRST.md         what ships, how the weeks run
  01-project-brief.md      the client, the users, the constraints
  02-week1.md              week 1, day by day: learn then do
  03-week2.md
  04-week3.md
  05-week4.md
  06-*.md  07-*.md  08-*.md  sprint references (accessibility gate, critique guide, glossary, ...)
  students/UX1..UX10/week*/ your work
  system/                  the shared design system (tokens and notes)
  delivery/                shared client-facing output (team leader only)
  fundamentals/            learning summaries, teardowns, drills
```

| Sprint | Weeks | Project | Focus |
|---|---|---|---|
| `Design-Sprint-1` | 0-4 | Kerala PSC application flow redesign | Set up, then visual craft and one complete flow |
| `Design-Sprint-2` | 5-8 | A skill scheme with a dropout problem | Research and problem framing |
| `Design-Sprint-3` | 9-12 and 12b | Sutra, a subscription app | Interaction, motion, metrics and ethics. The showpiece. Week 12b adds an AI-assisted coded prototype. |
| `Design-Sprint-4` | 13-16 | A health tech company, three products | Design systems, governance and adoption |
| `Design-Sprint-5` | 17-20 and 20b | Your choice of four, or your own | The capstone, with an AI-interface option. Week 20b is the Agent UX lab. |
| `Design-Sprint-6` | 21-24 | You | Portfolio, interview, and getting hired |

Kerala PSC brief: use public pages only. Never log in, register, apply or submit. Do not use personal profile screens.

Week 0 is setup: accounts, tools, your first commit and your first pull request. Week 12b and week 20b are extra project weeks that sit inside their sprints.

Admin material (model answers, rubrics, the sealed failure injections) is **not** in this repository. If a designer can read it, the defense is worthless.

## Your Figma files

The free Figma Starter plan gives you one team, one folder and three files. That is a hard limit, so we plan around it.

- **One Figma file per sprint**, named `SPRINT-N UX{n}`. Example: `SPRINT-3 UX4`.
- **One page per week** inside that file. Name the page for the week.
- Keep **one spare file** for experiments. Before starting a sprint, check the three-file limit; use Penpot when another sprint file would exceed it.
- The shared system does not live in its own file unless the admin or the Figma Education plan gives us libraries. Otherwise the system lives as tokens in `system/` (markdown or JSON) and you share it by view-only link.
- **Penpot is the backup.** It is free, open source, and runs in the browser. Use it when the Figma file limit blocks you. Check the Penpot pricing page before you rely on it.
- When using Penpot, follow the same file and page naming rules. A view-only Penpot link is accepted wherever a Figma link is requested.
- Figma Education (free Professional for eligible students) may lift the limits. Ask the admin. Do not assume it.

Install steps for both tools, Mac and Windows, are in `04-Tools-Setup.md`.

## How a day works

```
LEARN - 1 to 2 hours (morning)
  a named chapter, a named video, a named page

DO - 1.5 to 4 hours (afternoon)
  a task that uses exactly what you just learned
```

Save work in `Design-Sprint-N/students/UX{n}/weekX/`. Make one commit per task containing all files listed for that task. Use a message such as `Z0.5: add image and design link`.

Learning always comes first. Every task tells you what to learn before it, gives you the method, shows you a worked example, and states when you are done. Each task also includes an "If you get stuck" section. Day 6 is the cohort day: the shared system, a why session, a teardown, and the week's lab.

Some weeks also have a short **code corner**, 20 to 40 minutes: week 0, week 3, week 6, week 10, week 12b, week 15 and week 22. The steps are in `12-HTML-CSS-For-Designers.md`.

## What makes this program different

- **Evidence, not taste.** Every claim needs a source. Every critique names a user cost.
- **Gates, not opinions.** States, accessibility and evidence are checklists. Pretty work that fails a gate is not done.
- **A defense every sprint.** You explain your work from memory to reviewers who ask you to explain your decisions and evidence.
- **A failure injected in every sprint.** Real work changes under you. You write a post mortem.
- **A portfolio from Sprint 1.** Case-study drafts, a live site by week 12, three recorded mock interviews, and an honest external readiness check at the end.
- **AI used honestly.** Labs on working with it and on designing for it. Disclosure on everything it touches. Use free tiers only. Check the free limit before use for each AI tool. See `07-AI-In-Design.md`.
- **Code you can actually use.** You read and edit HTML and CSS, and you publish a small page. You do not become a programmer.
- **Current practice.** WCAG 2.2, the Design Tokens format, today's tools. See `09-Modern-Practice-Map.md`.

It does not promise a job. It promises you will know, honestly, where you stand.
