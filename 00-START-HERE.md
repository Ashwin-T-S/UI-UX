# 00 - START HERE

You are in the DOTSET Product Design cohort. 27 weeks. 10 designers. 6 sprints.

The weeks are week 0, weeks 1 to 24, plus week 12b and week 20b. Week 0 is setup. The b weeks are extra lab weeks.

This file tells you what to read, in what order, and what to do in your first three hours. Read this file completely before opening anything else.

---

## 1. The one rule of this program

**You learn a thing, then you use it straight away, then you write down what you learned.**

Not: read for three weeks then design. Not: design for three weeks then read.

Every single day has two blocks:

| Block | Time | What happens |
|---|---|---|
| **LEARN** | 1 to 2 hours | A named chapter, a named video, a named page. Nothing vague. |
| **DO** | 1 to 2 hours | A task that uses exactly what you just learned. |

At the end of the LEARN block you write a short summary and commit it. At the end of the DO block you commit the task output. Both are checked.

If you skip the LEARN block, the DO task will be impossible and you will guess. Guessing is the thing this program exists to remove.

## 5. Where your work goes

Everything you produce is committed to git. Nothing lives only in Figma, and nothing lives only in your head.

| What you make | Where it goes |
|---|---|
| Learning summary | `Design-Sprint-{s}/students/UX{designer}/week{week}/session{session}-learning.md` |
| Task output | `Design-Sprint-{s}/students/UX{designer}/week{week}/{TASK-ID}-{name}.md` |
| Figma screens | Figma is the canvas. One file per sprint, named `SPRINT-N UX{n}`, one page per week. Commit the view-only link inside a markdown file plus an exported PNG. |
| Penpot backup | Same rule. One file per sprint. Commit the view-only link inside a markdown file plus an exported PNG. |
| Shared system work | The sprint's `system/`. Final outputs: the sprint's `delivery/`, updated only by the team leader. |
| Weekly teardown and why session | the sprint's `fundamentals/` |
| Portfolio writing, reviews, interview scorecards | `Design-Sprint-{s}/students/UX{designer}/portfolio/` |
| Your AI log | `Design-Sprint-{s}/students/UX{designer}/ai-log.md` |

Allowed in the repo: markdown (`.md`), PNG/JPG under 2 MB (lowercase, hyphens, no spaces, e.g. `r1-1-home-page.png`), PDF under 10 MB, small `.html`, `.css` and `.js` files in code folders, and view-only Figma or Penpot links inside markdown files. Never commit `.fig` files, passwords, tokens, or real personal data. No real names, faces, phone numbers or IDs anywhere. Participants are P1, P2.

**One task, one commit containing all files listed for that task.** The commit message starts with the task ID, for example `C1.1 type scale with Malayalam test`.

## 7. Three things that will make you fail

**Skipping the learning block.** The task will take you four hours instead of one, and the result will be a guess. Every task in this program is written assuming you did the reading in that day's LEARN block.

**Not committing the learning summary.** It is 10 minutes of writing. It is also the only proof that you understood something, and it is what you will read back before the defense at the end of the sprint.

**Saving everything for one big push.** Commit each task when you finish it. If you submit all your work at the end of the week, others cannot give feedback while you work.
